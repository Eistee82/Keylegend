# Формат профиля устройства

Профиль устройства описывает одну модель клавиатуры в одной физической раскладке. Это единственный
файл в папке под `devices/`, названной `<производитель>-<модель>-<раскладка>`:

```
devices/razer-deathstalker-v2-de/
└── device.json     геометрия и соответствие светодиодов
```

`devices/device-profile.schema.json` описывает то же самое в машиночитаемом виде. Указание его в
строке `$schema`, как делают поставляемые профили, даёт большинству редакторов автодополнение и
подсветку ошибок прямо при наборе.

## device.json

```jsonc
{
  "$schema": "../device-profile.schema.json",
  "formatVersion": 1,
  "name": "Razer DeathStalker V2",
  "vendor": "Razer",
  "model": "DeathStalker V2",
  "physicalLayout": "ISO-DE",
  "canvas":  { "width": 439.5, "height": 135.5 },
  "matrix":  { "rows": 6, "columns": 22 },
  "verified": true,
  "keys": [
    { "id": "Keyboard_Escape", "x": 6, "y": 6, "width": 19, "height": 19,
      "row": 0, "column": 1, "label": "esc" }
  ]
}
```

| Поле | Значение |
|---|---|
| `formatVersion` | Редакция формата. Сейчас `1`. Сборка отклоняет профиль с номером выше, чем понимает. |
| `name` | То, что показывает интерфейс. |
| `vendor`, `model` | Кто её делает и какая модель. `"Generic"` — для профиля, описывающего раскладку, а не изделие. |
| `physicalLayout` | `ANSI-US`, `ISO-DE`, `JIS-JP`, `ABNT2-BR` … — физическое *расположение* клавиш, а не программная раскладка. |
| `canvas` | Система координат, к которой отнесены все положения. Значение имеют только соотношения; поставляемые профили считают в миллиметрах. |
| `matrix` | Размер светодиодной матрицы производителя. Клавиатуры Razer — 6 × 22 независимо от их размера. |
| `verified` | `true`, когда кто-то подтвердил соответствие на настоящем оборудовании. |
| `note` | Необязательный свободный текст для того, кто откроет файл следующим. |
| `image` | Необязательно и сейчас не используется — см. [Изображения](#изображения) ниже. |
| `keys[]` | По одной записи на клавишу. |

### Физическая раскладка, а не программная

`physicalLayout` определяет *форму* клавиатуры: высокая ли Г-образная клавиша ввода, есть ли
дополнительная клавиша слева от `Z`, несёт ли нижний ряд японские клавиши преобразования.

Он ничего не говорит о том, какие символы эти клавиши выдают. Об этом Keylegend спрашивает Windows
во время работы, для действующей сейчас раскладки. Поэтому профиль ISO-RU обслужит вашу клавиатуру
и тогда, когда Windows переключён на американскую раскладку или на Дворака, — оттого и есть по
одному профилю на *физическую* раскладку, а не на язык.

### Записи клавиш

| Поле | Значение |
|---|---|
| `id` | Уникальный идентификатор. Придерживайтесь существующих имён: `Keyboard_A`, `Keyboard_Enter`, `Keyboard_NonUsBackslash`, `Keyboard_Num7`. |
| `x`, `y` | Положение левого верхнего угла на полотне. |
| `width`, `height` | Размер клавиши на полотне. |
| `row`, `column` | Ячейка в светодиодной матрице производителя. Оба `null`, пока неизвестны, — это допустимое состояние, и именно для него существует калибровка. |
| `scanCode` | Переопределяет стандартный скан-код. Нужен только там, где физическая раскладка противоречит американским именам. |
| `parts` | Дополнительные прямоугольники той же клавиши, для клавиш непрямоугольной формы. |
| `label` | То, что напечатано на клавише, для клавиш, которые ничего не пишут. |
| `labelSecondary` | Вторая напечатанная строка, под первой. |

### Надписи принадлежат клавиатуре

`label` — это то, что *напечатано на колпачке*, а не перевод того, что клавиша делает. Немецкая
клавиатура говорит `strg`, французская — `ctrl`, итальянская — `bloc maiusc`, и каждая говорит это
независимо от того, на какой язык настроены меню Keylegend. Смена языка интерфейса никогда не
меняет надписи.

Клавиши, выдающие символ, вовсе не несут `label`. Их надпись берётся из действующей раскладки
Windows и потому сама следует за Shift, Caps Lock и AltGr.

### Клавиши с несколькими прямоугольниками

Клавиша ввода ISO — образцовый случай: одна клавиша на два ряда.

```jsonc
{
  "id": "Keyboard_Enter",
  "x": 267.25, "y": 72.5, "width": 23.75, "height": 19,
  "row": 3, "column": 14,
  "scanCode": 28,
  "parts": [ { "x": 262.5, "y": 53.5, "width": 28.5, "height": 19 } ],
  "label": "enter"
}
```

Главный прямоугольник несёт ячейку, `parts` добавляет остальную форму. Явный `scanCode` стоит там
потому, что верхняя половина занимает позицию, которую ANSI отводит обратной косой черте: без него
верх клавиши ввода красился бы так, будто печатает `\`.

### Скан-коды клавиш, которые есть только в одной раскладке

Стандартная таблица в `Keylegend.Core` покрывает то, что есть у американской клавиатуры. Клавиши,
существующие только в других раскладках, указывают свой код в профиле, чтобы ради раскладки не
приходилось менять C#:

| Идентификатор | Клавиша | `scanCode` |
|---|---|---|
| `Keyboard_JpYen` | `¥`, слева от Backspace в JIS | `0x7D` |
| `Keyboard_JpRo` | `ろ`, справа от правого Shift в JIS | `0x73` |
| `Keyboard_JpMuhenkan` | `無変換`, слева от пробела | `0x7B` |
| `Keyboard_JpHenkan` | `変換`, справа от пробела | `0x79` |
| `Keyboard_JpKana` | `かな` | `0x70` |
| `Keyboard_AbntC1` | клавиша `/?` справа от правого Shift в ABNT-2 | `0x73` |

## Правила, которые проверяет валидатор

Их проверяет непрерывная интеграция, поэтому профиль, нарушающий их, влить нельзя:

- Идентификаторы клавиш уникальны
- Никакие две клавиши не претендуют на одну ячейку матрицы
- Никакие две клавиши не перекрываются на полотне
- `row` и `column` заданы оба или оба равны `null`
- Ячейки лежат внутри объявленной матрицы
- Клавиши лежат внутри полотна
- У каждой клавиши положительный размер
- Изображение, названное в `image`, действительно существует

## Именование и различие ISO/ANSI

Идентификаторы клавиш следуют американской раскладке, потому что так же поступает и сама матрица
производителя. На немецкой клавиатуре физическая `Z` поэтому сидит на `Keyboard_Y` и наоборот. Это
касается только имени: ни положение, ни поведение от этого не зависят, ведь настоящий символ
запрашивается у Windows во время работы.

Два идентификатора существуют только на клавиатурах ISO:

| Идентификатор | Клавиша | Ячейка Razer |
|---|---|---|
| `Keyboard_NonUsBackslash` | дополнительная клавиша слева от `Y`/`Z` (`<`, `>`, `\|`) | `RZKEY_EUR_2`, ряд 4 столбец 2 |
| `Keyboard_NonUsTilde` | клавиша рядом с вводом в среднем ряду (`#`, `'`) | `RZKEY_EUR_1`, ряд 3 столбец 13 |

На клавиатурах ISO высокая клавиша ввода занимает две позиции матрицы: верхнюю половину там, где у
ANSI обратная косая черта (ряд 2, столбец 14), нижнюю — на `Keyboard_Enter` (ряд 3, столбец 14).

**Загораются ли на деле обе, зависит от модели.** Таблица производителя описывает, что матрица
может *адресовать*, а не что у конкретной клавиатуры *установлено*. На DeathStalker V2 калибровка
показала, что верхняя ячейка не управляет никаким светодиодом: всю клавишу ввода освещает нижняя,
и поэтому поставляемый профиль описывает ввод как одну клавишу с двумя прямоугольниками, а не как
две клавиши.

Именно такое из документации вывести нельзя, и именно поэтому профиль не следует помечать
`verified`, пока кто-нибудь не прошёл его на оборудовании.

## Изображения

`image` необязательно и сейчас не используется: просмотр на экране рисуется из геометрии выше.
Рисование сохраняет чёткость просмотра при любом размере окна и делает невозможным расхождение
изображения с профилем.

Если вы всё же прикладываете изображение, это должно быть изображение, которое сняли или создали
**вы**. Весь этот репозиторий выходит под лицензией MIT, дающей каждому право изменять и
распространять его содержимое, — право, которого никто не может дать на продуктовую фотографию
производителя клавиатур. См. [NOTICE.md](../../NOTICE.md).
