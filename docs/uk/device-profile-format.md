# Формат профілю пристрою

Профіль пристрою описує одну модель клавіатури в одній фізичній розкладці. Це єдиний файл у теці
під `devices/`, названій `<виробник>-<модель>-<розкладка>`:

```
devices/razer-deathstalker-v2-de/
└── device.json     геометрія та відповідність світлодіодів
```

`devices/device-profile.schema.json` описує те саме в машиночитному вигляді. Зазначення його в
рядку `$schema`, як роблять постачальні профілі, дає більшості редакторів доповнення й підсвічування
помилок просто під час набору.

## device.json

```jsonc
{
  "$schema": "../device-profile.schema.json",
  "formatVersion": 1,
  "name": "Razer DeathStalker V2",
  "vendor": "Razer",
  "model": "DeathStalker V2",
  "physicalLayout": "ISO-DE",
  "canvas":  { "width": 439.5, "height": 135.5 },
  "matrix":  { "rows": 6, "columns": 22 },
  "verified": true,
  "keys": [
    { "id": "Keyboard_Escape", "x": 6, "y": 6, "width": 19, "height": 19,
      "row": 0, "column": 1, "label": "esc" }
  ]
}
```

| Поле | Значення |
|---|---|
| `formatVersion` | Редакція формату. Наразі `1`. Збірка відхиляє профіль із номером вищим, ніж розуміє. |
| `name` | Те, що показує інтерфейс. |
| `vendor`, `model` | Хто її робить і яка модель. `"Generic"` — для профілю, що описує розкладку, а не виріб. |
| `physicalLayout` | `ANSI-US`, `ISO-DE`, `JIS-JP`, `ABNT2-BR` … — фізичне *розташування* клавіш, а не програмна розкладка. |
| `canvas` | Система координат, до якої віднесено всі положення. Значення мають лише співвідношення; постачальні профілі рахують у міліметрах. |
| `matrix` | Розмір світлодіодної матриці виробника. Клавіатури Razer — 6 × 22 незалежно від їхнього розміру. |
| `verified` | `true`, коли хтось підтвердив відповідність на справжньому обладнанні. |
| `note` | Необов'язковий вільний текст для того, хто відкриє файл наступним. |
| `image` | Необов'язково і зараз не використовується — див. [Зображення](#зображення) нижче. |
| `keys[]` | По одному запису на клавішу. |

### Фізична розкладка, а не програмна

`physicalLayout` визначає *форму* клавіатури: чи висока Г-подібна клавіша вводу, чи є додаткова
клавіша ліворуч від `Z`, чи несе нижній ряд японські клавіші перетворення.

Він нічого не каже про те, які символи ці клавіші видають. Про це Keylegend запитує Windows під час
роботи, для чинної зараз розкладки. Тому профіль ISO-UK обслужить вашу клавіатуру й тоді, коли
Windows перемкнено на американську розкладку або на Дворака, — звідси й один профіль на *фізичну*
розкладку, а не на мову.

### Записи клавіш

| Поле | Значення |
|---|---|
| `id` | Унікальний ідентифікатор. Дотримуйтесь наявних імен: `Keyboard_A`, `Keyboard_Enter`, `Keyboard_NonUsBackslash`, `Keyboard_Num7`. |
| `x`, `y` | Положення лівого верхнього кута на полотні. |
| `width`, `height` | Розмір клавіші на полотні. |
| `row`, `column` | Комірка у світлодіодній матриці виробника. Обидва `null`, доки невідомі, — це припустимий стан, і саме для нього існує калібрування. |
| `scanCode` | Перевизначає стандартний скан-код. Потрібен лише там, де фізична розкладка суперечить американським іменам. |
| `parts` | Додаткові прямокутники тієї самої клавіші, для клавіш непрямокутної форми. |
| `label` | Те, що надруковано на клавіші, для клавіш, які нічого не пишуть. |
| `labelSecondary` | Другий надрукований рядок, під першим. |

### Написи належать клавіатурі

`label` — це те, що *надруковано на ковпачку*, а не переклад того, що клавіша робить. Німецька
клавіатура каже `strg`, французька — `ctrl`, італійська — `bloc maiusc`, і кожна каже це незалежно
від того, якою мовою налаштовані меню Keylegend. Зміна мови інтерфейсу ніколи не змінює написів.

Клавіші, що видають символ, зовсім не несуть `label`. Їхній напис береться з чинної розкладки
Windows і тому сам слідує за Shift, Caps Lock і AltGr.

### Клавіші з кількома прямокутниками

Клавіша вводу ISO — взірцевий випадок: одна клавіша на два ряди.

```jsonc
{
  "id": "Keyboard_Enter",
  "x": 267.25, "y": 72.5, "width": 23.75, "height": 19,
  "row": 3, "column": 14,
  "scanCode": 28,
  "parts": [ { "x": 262.5, "y": 53.5, "width": 28.5, "height": 19 } ],
  "label": "enter"
}
```

Головний прямокутник несе комірку, `parts` додає решту форми. Явний `scanCode` стоїть там тому, що
верхня половина займає позицію, яку ANSI відводить зворотній скісній рисці: без нього верх клавіші
вводу фарбувався б так, ніби він друкує `\`.

### Скан-коди клавіш, що є лише в одній розкладці

Стандартна таблиця в `Keylegend.Core` покриває те, що має американська клавіатура. Клавіші, які
існують лише в інших розкладках, зазначають свій код у профілі, щоб заради розкладки не доводилося
міняти C#:

| Ідентифікатор | Клавіша | `scanCode` |
|---|---|---|
| `Keyboard_JpYen` | `¥`, ліворуч від Backspace у JIS | `0x7D` |
| `Keyboard_JpRo` | `ろ`, праворуч від правого Shift у JIS | `0x73` |
| `Keyboard_JpMuhenkan` | `無変換`, ліворуч від пробілу | `0x7B` |
| `Keyboard_JpHenkan` | `変換`, праворуч від пробілу | `0x79` |
| `Keyboard_JpKana` | `かな` | `0x70` |
| `Keyboard_AbntC1` | клавіша `/?` праворуч від правого Shift у ABNT-2 | `0x73` |

## Правила, які перевіряє валідатор

Їх перевіряє неперервна інтеграція, тож профіль, що їх порушує, влити не можна:

- Ідентифікатори клавіш унікальні
- Жодні дві клавіші не претендують на одну комірку матриці
- Жодні дві клавіші не перекриваються на полотні
- `row` і `column` задано обидва або обидва дорівнюють `null`
- Комірки лежать усередині оголошеної матриці
- Клавіші лежать усередині полотна
- Кожна клавіша має додатний розмір
- Зображення, назване в `image`, справді існує

## Іменування та різниця ISO/ANSI

Ідентифікатори клавіш тримаються американської розкладки, бо так само чинить і сама матриця
виробника. На німецькій клавіатурі фізичне `Z` тому сидить на `Keyboard_Y` і навпаки. Це стосується
лише імені: ні положення, ні поведінка від цього не залежать, адже справжній символ запитується у
Windows під час роботи.

Два ідентифікатори існують лише на клавіатурах ISO:

| Ідентифікатор | Клавіша | Комірка Razer |
|---|---|---|
| `Keyboard_NonUsBackslash` | додаткова клавіша ліворуч від `Y`/`Z` (`<`, `>`, `\|`) | `RZKEY_EUR_2`, ряд 4 стовпець 2 |
| `Keyboard_NonUsTilde` | клавіша поруч із вводом у середньому ряду (`#`, `'`) | `RZKEY_EUR_1`, ряд 3 стовпець 13 |

На клавіатурах ISO висока клавіша вводу займає дві позиції матриці: верхню половину там, де в ANSI
зворотна скісна риска (ряд 2, стовпець 14), нижню — на `Keyboard_Enter` (ряд 3, стовпець 14).

**Чи засвічуються насправді обидві, залежить від моделі.** Таблиця виробника описує, що матриця
може *адресувати*, а не що в конкретної клавіатури *встановлено*. На DeathStalker V2 калібрування
показало, що верхня комірка не керує жодним світлодіодом: усю клавішу вводу освітлює нижня, і саме
тому постачальний профіль описує ввід як одну клавішу з двома прямокутниками, а не як дві клавіші.

Саме такого з документації вивести не можна, і саме тому профіль не слід позначати `verified`, доки
хтось не пройшов його на обладнанні.

## Зображення

`image` необов'язкове і зараз не використовується: перегляд на екрані малюється з геометрії вище.
Малювання зберігає чіткість перегляду за будь-якого розміру вікна й унеможливлює розходження
зображення з профілем.

Якщо ви все ж додаєте зображення, це має бути зображення, яке зняли або створили **ви**. Увесь цей
репозиторій виходить за ліцензією MIT, що дає кожному право змінювати й поширювати його вміст, —
право, якого ніхто не може надати на продуктову фотографію виробника клавіатур. Див.
[NOTICE.md](../../NOTICE.md).
