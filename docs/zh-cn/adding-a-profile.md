# 添加配置

应用程序配置是**数据，不是代码**。你不需要 C#，也不需要构建工具——一个文本编辑器，加上对该程序的
真正了解就够了，而后一半才是难的。

如果你只想给自己弄一份配置，在界面里做即可：它会存进 `settings.json`，与这里说的一切无关。放在
`profiles/` 下的文件，是让一份配置随程序发给所有人的方式。

## 1. 建立文件

```
profiles/apps/<id>.json      程序
profiles/games/<id>.json     游戏
```

文件名必须与其中的 `id` 一致。小写，`a-z0-9-`。构建会按通配符嵌入这两个目录中的每一个文件，因此没
有任何项目文件需要改动。

id 是永久的。用户覆盖和隐藏配置的记录都以它为键，因此在后续版本中改名会让别人的修改成为孤儿。挑一
个即便程序换了品牌名也依然成立的名字——`adobe-photoshop`，而不是 `photoshop-2026`。

## 2. 填写内容

字段、三个小节、功能分组、修饰键组合以及颜色约定，都记在
[profiles/FORMAT.md](../../profiles/FORMAT.md) 里。请先读它；那是参考文档，本页不再重复。

下面讲的是即便读过格式说明也照样会出岔子的部分。

## 3. 位置和字符不是一回事

按键 id 来自设备配置，命名的是**美式位置**。`Keyboard_Y` 是在美式键盘上打出 `Y` 的那个物理键——在
德语键盘上，那个键打出的是 `Z`。因此格式提供了两种给按键命名的方式，选错的那种会产出一份在所有非
美式布局上明显错误、却在编写它的那台机器上看着完美的配置。

每一条都该问：它到底讲的是什么？

- **手放在哪里 → 位置。** 为 WASD 做的高亮讲的是手指摆出的形状，而不是字母。`Keyboard_W`、
  `Keyboard_A`、`Keyboard_S`、`Keyboard_D` 在任何地方都是正确的键。
- **命令是什么 → 字符。** `Ctrl+Z` 的意思是“打出 z 的那个键”。若写成位置，在德语键盘上撤销与重做
  看起来就是反的。
- **不打出任何字符的键 → 又是位置。** Esc、Tab、回车、退格、方向键和功能键没有字符，因此
  `shortcuts.keys` 用 id 指称它们，毫无歧义。

### 对高亮而言，取决于程序如何读取键盘

QWERTZ 与 QWERTY 恰好只在两处不同，所以 `Keyboard_Y` 和 `Keyboard_Z` 是唯一可能出错的 id。而且它
们出错时悄无声息。

高亮的 id 永远是**物理位置**。问题在于程序指的是哪个物理键，而这取决于它如何读取键盘：

| 程序绑定到 | 例子 | 其文档中的 `Z` 意味着 |
|---|---|---|
| **字符**（Windows 虚拟键码，随布局变动） | Photoshop、Blender、GIMP、Krita —— 一般的应用程序 | `Keyboard_Y` —— 上排那个键，在德语键盘上打出 `Z` |
| **位置**（扫描码，多数游戏引擎如此，好让 WASD 待在原处） | 一般的游戏 | `Keyboard_Z` —— 下排那个键 |

如果你无法确定某个程序究竟以哪种方式读取键盘，就把 `Y` 和 `Z` 的条目略去。其余字母一概不受影响。

## 4. 拿不准的就别写

错的快捷键比缺的快捷键更糟。缺失的条目只是让一个键保持暗着，什么代价也没有；错误的条目却让键盘宣
称一件不实之事，而用户没有办法看出它不实。标签让这一主张变得明确——却不会让它变得正确。

所以：

- 只写下你有把握是该程序**默认**绑定的内容，即刚装好、原封未动的状态。你自己的安装不是依据；你多
  半改过什么又忘了。
- 对照程序自己的文档，或对照设置未经改动的程序本身核实。
- 若默认值在不同版本间有出入，以当前版本为准。
- 不要臆造。若某程序对某项功能并无广为人知的快捷键，那它就没有条目。

十二条正确的快捷键，胜过三十条里错了四条。高亮标签同理：如果你说不出某个键做什么，那就是这条尚不
属于该配置的信号。

## 5. 测试

```bash
dotnet test
```

配置测试会检查 `profiles/` 下的每个文件：id 唯一且与文件名一致，`kind` 与所在目录相符，每个按键 id
都存在于某份随附设备配置中，颜色可以解析，分组与修饰键组合有效且写成规范形式，每条快捷键都带标
签，没有字母键出现在 `shortcuts.keys` 之下（它该在 `characters` 里），没有配置是空的，也没有两份
配置在不用 `titleContains` 相互区分的情况下争抢同一个可执行文件。

有一件事是**刻意不检查**的：同一个修饰键之下出现两次相同的标签。它看起来像是抓复制粘贴疏漏的办
法，实际抓到的却是真正的别名——浏览器用 `Ctrl+W` 和 `Ctrl+F4` 都能关闭标签页。会对正确数据报警的检
查，比没有检查更糟。

任何测试都无法检查的，是某条快捷键是否*属实*。那正是评审的用途，也是每条都带一个可供评审的标签的
原因。

## 6. 对着程序试一试

启动 Keylegend，把程序切到前台，按住你的配置所定义的修饰键。预览显示的内容与键盘一致，因此就这一
步而言，一台没有 Chroma 硬件的笔记本也够用。把它与程序自己的菜单对照——凡是你在程序里找不到其标签
的命令，都该第一个删掉。

## 7. 发起 pull request

请说明你是对着哪个程序、哪个版本核对的，以及你如何验证这些绑定：程序自己的文档、程序本身，还是两
者兼有。参见 [CONTRIBUTING.md](../../CONTRIBUTING.md)。

一份小而确凿的配置是好的贡献。一份大而半凭记忆的则不是。
