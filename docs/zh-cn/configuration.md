# 配置

设置位于 `%APPDATA%\Keylegend\`，通过界面修改。首次启动时会写出一份完整的默认配置。

## 颜色

每个类别一种颜色：

| 类别 | 适用于 |
|---|---|
| 数字 | `1`、`7`，以及 Num Lock 开启时的小键盘 |
| 小写字母 | `a`、`ö` |
| 大写字母 | `A`、`Ö` |
| 符号 | `+`、`#`、`€`、`\|`，以及小键盘上的运算符 |
| 控制键 | Esc、Tab、回车、退格、修饰键、方向键、导航区，以及 Num Lock 关闭时的小键盘 |
| 功能键 | F1 至 F12 |
| 死键 | `^`、`´`、`` ` `` —— 需要再按一次才能产生字符的键 |
| 未分配 | 在当前情境下没有含义的键；默认为暗。Num Lock 关闭时小键盘的中心键是最清楚的例子 |

锁定键各有两种颜色——一种代表开启，一种代表关闭。

## 快捷键集合

一个快捷键集合把按键映射到**功能分组**，并按当前按住的修饰键来选取。随附的集合有：`Win`、
`Win+Shift`、`Win+Ctrl`、`Alt`、`Ctrl`、`Ctrl+Shift`、`Ctrl+Alt`。

每个分组有自己的颜色，因此相关命令读起来是一整块——例如编辑（`X`/`C`/`V`/`Z`/`Y`/`A`）用一种颜色，
文件操作（`N`/`O`/`S`/`P`/`W`）用另一种。

Windows 快捷键在全系统范围内固定，因此始终准确。Ctrl 快捷键因程序而异；随附集合覆盖的是常见的
Windows 惯例。

## 应用程序配置

一份配置描述某个程序处于前台时键盘该显示什么。随程序附带约九十份——诸如 Photoshop、Visual Studio
Code 或 Excel 这样的程序，以及 Elden Ring 或 Counter-Strike 2 这样的游戏。它们自行生效：相应窗口
一获得焦点，配置即告适用；焦点转走后，默认集合重新生效。没有配置匹配的地方，什么都不变。

识别依据是可执行文件名。当匹配的配置不止一份时，指名该程序的那份胜出——因此拥有自己配置的游戏会保
留它，哪怕游戏检测同样触发。优先级只用于打破剩下的平局。

一份配置只替换它自己点名的修饰键层。Photoshop 替换 Ctrl 层，因为 Ctrl 在那里意味着别的命令；
`Win+E` 依然打开资源管理器，因为 Windows 在全系统范围内分配该组合，而且不论前台是什么它都成立。

### 一份配置包含什么

| 小节 | 内容 |
|---|---|
| 匹配 | 该配置适用于哪些程序：可执行文件名、是否泛指所有被检测到的游戏，以及优先级 |
| 高亮 | 固定为某一颜色的按键，与其产生的字符无关——游戏中的 WASD、图像编辑器的工具键 |
| 快捷键 | 对单个修饰键层的替换：`Ctrl` 之下哪个键承载哪条命令，按功能分组着色 |

高亮和快捷键还带有说明命令作用的标签——“复制图层”“跳跃”。这些在键盘上一概看不到；LED 只显示颜色。
标签出现在程序内的预览中，而在九十份配置的规模上，它是核对某一条是否正确的唯一途径。

### 编辑与恢复

三个小节各自独立地被覆盖。编辑随附配置的高亮，从此高亮就归你：它们被冻结，不再跟随随附版本。匹配
和快捷键则继续跟随，并会得到新版本带来的改进。

只有你改动的那个小节会被保存，且以配置的 id 为键——绝不是整份配置的副本。这正是恢复之所以存在的原
因，也是更新仍能改进你已部分编辑过的配置的原因。

因此恢复同样按小节进行：交还快捷键而保留自己的高亮是可以的。恢复整份配置会收回每一个小节，外加改
过的名称和隐藏状态。

随附配置可以**隐藏但不能删除**。它们存在于程序文件之内；删掉一份也只能维持到下次启动。被隐藏的配
置在选取配置时会被跳过，但仍留在列表中，可以重新显示。

### 你自己的配置

你自己创建的配置会整份存进 `settings.json`，因为没有什么可与之比对。因此它无法恢复，只能删除。其
余方面它与随附配置无异：同样的三个小节，同样的选取规则。

如果一份配置应当对所有人生效而不只是对你，它就该以文件的形式进入项目——参见
[添加配置](adding-a-profile.md)。

### 设置文件格式

`settings.json` 带有 `formatVersion` 3。更早的文件会在加载时迁移。

版本 1 的文件既不认识 id，也没有记录配置的来源，因此说不出它的哪些条目是随附的。它们全部变成用户配置。
什么都不会丢失，但随附配置会并列出现，所以起初同一个程序可能有两条；多余的那条可以删除或隐藏。

版本 2 的文件列出所有颜色，连没人碰过的也一并列入，于此把调色板钉死：改进过的出厂颜色到不了任何
先前运行过本程序的人手上。因此，与该版本调色板相同的颜色在迁移时会被当作默认值丢弃；其余都是您的
选择，会保留下来。
## 行为

| 设置 | 含义 |
|---|---|
| 空闲时交还灯光 | 是否交还。关闭后，Keylegend 会一直占用键盘，直到你暂停或关闭它——并且在启动时就接管，而不是等待按键。 |
| 空闲时长 | 交还之前键盘无操作的秒数。默认 60——重新取回需要一到两秒，因此时长过短会让这变成持续不断的打断。交还功能关闭期间该值仍会保留。 |
| 亮度 | 0 到 100 % 的全局系数，在合成帧时施加于每一种颜色。 |
| 使用应用程序配置 | 是否查阅配置。关闭后，默认集合在任何地方都生效，不论前台是什么。 |
| 随 Windows 启动 | 以 `--minimized` 开关把程序登记到 `Run` 键。这样启动时，Keylegend 出现在通知区域：没有窗口，也没有气泡提示。手动启动则总会显示窗口。由早期版本写入的条目会在下次启动时更新。 |

## 语言

界面跟随 Windows 的显示语言，提供十一种：英语、德语、西班牙语、法语、意大利语、荷兰语、波兰语、
葡萄牙语、俄语、乌克兰语和简体中文。**设置 → 语言**可以覆盖它；切换立即生效，无需重启。

列表中每种语言都以自己的语言书写自己的名字，而不是被翻译。翻译它意味着十一种语言各自都要带着其余
十种的名称，而界面以某人读不懂的语言启动时，他就得在同样读不懂的语言里去找自己的那一项。

选择保存在 `settings.json` 的 `language` 之下，取值为 `Automatic`、`English`、`German`、
`Spanish`、`French`、`Italian`、`Dutch`、`Polish`、`Portuguese`、`Russian`、`Ukrainian` 或
`ChineseSimplified`。无法识别的取值会退回 `Automatic`，而不是拒绝启动——手工改过的文件多半也正是
这个意思。

被翻译的是菜单和说明文字。有两样**不**翻译，且都是有意为之：

- 所绘键盘上的**键帽字样**。它们来自 Razer 的图纸，必须与你面前的键盘相符，而不是与菜单的语言相符——德
  语 ISO 键盘显示 `strg` 和 `entf`，不论界面是否以英文运行。
- **修饰键的名称**（Shift、Ctrl、Alt、AltGr、Num Lock ……）。同样的名称由快捷键机制为层列表生成，
  而那部分位于翻译之外；翻一半会比完全不翻更难读。

凡是没有翻译的内容都会退回英文，因此一份未完成的语言文件只会让缺失的那几行显示为英文，而不会拖垮
整个界面。

## 如果灯光不工作

与 Chroma 服务的通信可能失败：服务已停止、Synapse 被关闭、另一个程序占着会话。Keylegend
会继续重试，尝试之间的间隔逐渐拉长，同时把出了什么问题说出来：

- 窗口底部的状态行写出原因，用琥珀色而不是平常的灰色
- 通知区域在提示里说明，这样关着的窗口也藏不住它
- 一条气泡通知宣告一次——每次故障一次，而不是每次重试一次

只要有一帧重新送达，这三处都会消失。如果什么都没出现而键盘依然不亮，那是程序没在运行——
到通知区域找它的图标。

## 如果亮错了键

窗口里的键盘就是桌上的键盘：两者由同一份代码填充，所以窗口显示的就是硬件应有的样子。把两者并排比对，
就是检验。

一个键属于灯光矩阵的哪个单元，是 Synapse 与图纸都不说的唯一一件事——它来自 Chroma
协议自带的表。所以，如果硬件上亮起的键与窗口里亮着的不是同一个，那张表对你的型号就是错的。
这时值得开一个问题单，说明是哪块键盘、哪个键。
